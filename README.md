# PC1500 Expansion Module (PSoC 5)

A PSoC 5-based hardware expansion board for the Sharp PC-1500/PC-2 pocket
computer, adding SD-card storage to PC-1500 BASIC via a set of new
`SD`-prefixed keywords (`SDLOAD`, `SDSAVE`, `SDLS`, `SDFMT`, ...).

The board plugs into the PC-1500's expansion port the same way a Sharp
CE-150/153/158 peripheral would, but unlike those (and unlike a real memory
module), the PSoC side has **no bus-request (BRQ) line** — it can't halt the
LH5801 CPU and take over the bus directly. Instead, the two sides
communicate through a shared 4KB RAM window mapped into the PC-1500's
address space: the CPU writes a command byte to a fixed "instruction"
address, the PSoC (polling that address in its own main loop) picks it up,
does the work, and writes its response into the same shared window. See
`PC_EXP.h` for the full wire protocol (command/status codes, buffer
layout).

## Companion emulator

[`pc1500emu`](https://github.com/pchambre/pc1500emu) is a from-scratch
PC-1500/LH5801 emulator with a matching `ExpansionMock` that implements this
same protocol against a real host directory — most of this board's firmware
and expansion-ROM development happens against the emulator (fast, no
hardware round-trip needed) and is only periodically verified against the
real PSoC board.

## Layout

This repo is a PSoC Creator workspace (`PC1500-PSOC5.cywrk`) containing
several `.cydsn` design variants, built up over the course of development.
**`Design01_NonDMA_8K_PV_Swap.cydsn` is the current, active design** — the
others (`Design01.cydsn`, `Design01_NonDMA.cydsn`,
`Design01_NonDMA_8KAddress_Space*.cydsn`, `Design01_NonDMA_8K_Swap2ndPage.cydsn`,
`Design02.cydsn`) are earlier iterations kept for reference, not maintained.

Inside the active design:

- `TopDesign/` — the PSoC 5 schematic (open with PSoC Creator to edit).
- `main.c` / `PC_EXP.h` — the PSoC-side firmware: the command processor
  (`DoCommand()`) that implements the shared-window wire protocol, backed
  by SEGGER emFile for the actual SD card filesystem calls.
- `rom/` — the PC-1500 expansion ROM, hand-written LH5801 assembly
  (`rom.asm`) that installs the new BASIC keywords. Assembled with
  [`sdaslh5801`](https://github.com/pchambre/sdcc-pc1500) via `build.ps1`,
  producing `rom_image.h` (baked into the PSoC firmware image so the module
  presents this ROM to the PC-1500 at boot) and a standalone `rom_9000.bin`
  (loadable directly into `pc1500emu` for fast iteration without a full
  PSoC Creator rebuild). See `rom/tests/` for a couple of small standalone
  test keywords used while reverse-engineering the PC-1500's own keyword
  dispatch mechanism.
- `SDCard/` — the emFile SD-card component wrapper.

Everything under `Generated_Source/`, `CortexM3/`, `codegentemp/`, and
`Export/` in each `.cydsn` folder is regenerated by PSoC Creator on build
and isn't tracked (see `.gitignore`) — open the workspace in PSoC Creator
and build to recreate it.

## Commands (implemented in `rom/rom.asm`)

- **`SDLS`** — browse the SD card's file listing.
- **`SDFMT`** — format the SD card (`Y`/`N` confirmation).
- **`SDLOAD`** — load a BASIC program or binary data:
  - `SDLOAD` — browse, `L` selects and loads, `Enter` ignored, `CL`/`BREAK` abort.
  - `SDLOAD "<filename>"` — direct load, no browser.
  - `SDLOAD M` — browse, `L` loads the selected file as binary to its
    header's target address.
  - `SDLOAD M "<filename>"` — direct binary load to the file's header
    address; also `CALL`s an address embedded in the file, if present.
  - `SDLOAD M "<filename>",<address>` — direct binary load, relocated to
    `<address>` (decimal or `&`-prefixed hex); never calls the embedded
    address.
  - A missing file raises a genuine BASIC `ERROR 40`.
- **`SDSAVE`** — save a BASIC program or binary data:
  - `SDSAVE "<filename>"[,-Y]` — saves the current BASIC program.
  - `SDSAVE M "<filename>",<start>,<end>[,<call>][,-Y]` — saves the
    inclusive RAM range `[start,end]` as binary, with an optional embedded
    call address for a later `SDLOAD M` to invoke automatically.
  - Both forms prompt to confirm before overwriting an existing file
    (`-Y` skips the prompt); missing/malformed required arguments raise
    `ERROR 1`.

`SDDF`, `SDRM`, `SDCP`, `SDCD`, `SDMKDIR`, `SDRMDIR`, `SDPWD` are registered
in the keyword table but still stubs (no real implementation yet).

BASIC-mode `SDLOAD`/`SDSAVE` target the program area's real, live start
address (tracked by BASIC itself in RAM at `7865H`/`7866H`, which shifts
depending on installed RAM — e.g. a CE-155 module moves it to `38C5H`),
not a hardcoded address, so they work correctly regardless of the PC-1500's
RAM configuration.

## Building

Requires PSoC Creator (this workspace was last built with PSoC Creator
4.x). Open `PC1500-PSOC5.cywrk`, select `Design01_NonDMA_8K_PV_Swap.cydsn`
as the active design, and Build. The ROM assembly step
(`rom/build.ps1`, needing `sdaslh5801` on `PATH`) must be run first if
`rom.asm` changed, so `rom_image.h` is up to date before the PSoC-side
build picks it up.
